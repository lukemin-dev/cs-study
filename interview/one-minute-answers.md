# One-Minute Answers

이 문서는 면접에서 1분 안에 말할 답변을 모으는 공간입니다.

## 자기소개형 프로젝트 설명

저는 반복되는 문제를 자동화하고, 문제가 생겼을 때 추적 가능한 구조를 만드는 데 관심이 있습니다. 예를 들어 Java Socket 기반 채팅 프로젝트에서는 여러 클라이언트를 동시에 처리하기 위해 Thread Pool을 사용했고, TCP의 스트림 특성 때문에 메시지 경계가 깨질 수 있다는 점을 고려해 length-prefix 프로토콜을 구현했습니다. 또 학기 플래너 자동화 프로젝트에서는 설정 파일을 기반으로 GitHub 라벨, 마일스톤, 이슈를 생성해 반복 작업을 줄이는 흐름을 만들었습니다.

## TCP 설명

TCP는 연결을 맺고 데이터의 순서와 재전송을 보장하는 전송 방식입니다. 신뢰성이 중요하지만 UDP보다 상대적으로 무겁습니다. 채팅이나 파일 전송처럼 데이터가 누락되면 안 되는 서비스에 적합합니다. 제 채팅 프로젝트에서는 메시지 신뢰성이 중요해서 TCP를 사용했고, TCP가 메시지 경계를 보장하지 않는 문제를 length-prefix 방식으로 처리했습니다.

## Thread 설명

스레드는 프로세스 안에서 실행되는 작업 흐름입니다. 여러 작업을 동시에 처리할 수 있게 해주지만, 같은 메모리를 공유하기 때문에 동시성 문제를 조심해야 합니다. 제 채팅 서버에서는 여러 클라이언트를 동시에 처리하기 위해 클라이언트마다 `ClientSession`을 만들고 Thread Pool에서 실행했습니다.
