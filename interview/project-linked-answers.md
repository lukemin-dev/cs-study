# Project-Linked CS Answers

이 문서는 CS 개념을 내 프로젝트와 연결해서 말하는 연습용 문서입니다.

## TCP와 채팅 프로젝트

### 질문

채팅 프로젝트에서 왜 TCP를 사용했나요?

### 답변

채팅 메시지는 누락되거나 순서가 바뀌면 사용자가 대화를 이해하기 어렵기 때문에 신뢰성 있는 전송이 중요하다고 생각했습니다. 그래서 UDP가 아니라 TCP Socket을 사용했습니다. 다만 TCP는 메시지 단위가 아니라 바이트 스트림 기반이기 때문에, 메시지가 잘리거나 붙어서 들어올 수 있습니다. 이를 해결하기 위해 메시지 앞에 payload 길이 4바이트를 붙이는 length-prefix 방식을 사용했습니다.

## Thread와 채팅 서버

### 질문

채팅 서버에서 스레드를 왜 사용했나요?

### 답변

채팅 서버는 여러 클라이언트가 동시에 접속할 수 있어야 합니다. 한 클라이언트의 입력을 기다리는 동안 서버 전체가 멈추면 안 되기 때문에, 클라이언트마다 `ClientSession`을 만들고 Thread Pool에서 실행하도록 구성했습니다. 이렇게 하면 여러 접속자의 메시지를 동시에 처리할 수 있습니다.

## 동시성 자료구조

### 질문

접속자 목록에 왜 일반 HashSet을 쓰지 않았나요?

### 답변

접속자 목록은 여러 클라이언트 세션 스레드가 동시에 추가, 삭제, 조회할 수 있습니다. 일반 `HashSet`은 동시 접근에 안전하지 않기 때문에 문제가 생길 수 있습니다. 그래서 `ConcurrentHashMap.newKeySet()`을 사용해 여러 스레드가 동시에 접근해도 안전하게 관리하도록 했습니다.

## GitHub Actions와 자동화

### 질문

2025-fall-planner에서 GitHub Actions를 왜 사용했나요?

### 답변

반복적으로 해야 하는 라벨 생성, 마일스톤 생성, 주간 이슈 생성을 수동으로 하면 실수하기 쉽고 시간이 걸립니다. 그래서 설정 파일에 과제 정보를 적고, GitHub Actions나 로컬 스크립트가 이를 읽어 자동으로 이슈를 만들도록 구성했습니다. 이때 `--apply` 옵션을 둬서 먼저 미리보기로 확인하고, 필요할 때만 실제 GitHub에 반영하도록 했습니다.
