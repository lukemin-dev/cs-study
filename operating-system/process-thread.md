# Process vs Thread

## 한 줄 정의

프로세스는 실행 중인 프로그램이고, 스레드는 프로세스 안에서 실제 작업을 수행하는 실행 흐름입니다.

## 왜 필요한가

하나의 프로그램이 여러 작업을 동시에 처리해야 하는 경우가 많기 때문입니다.

예를 들어 채팅 서버는 한 명의 클라이언트만 상대하면 안 됩니다. 여러 클라이언트가 동시에 접속하고 메시지를 보내도 서버가 계속 응답해야 합니다.

## 핵심 차이

| 구분 | 프로세스 | 스레드 |
| --- | --- | --- |
| 의미 | 실행 중인 프로그램 | 프로세스 내부 실행 흐름 |
| 메모리 | 독립적인 메모리 공간 | 같은 프로세스 메모리 공유 |
| 생성 비용 | 상대적으로 큼 | 상대적으로 작음 |
| 예시 | 브라우저 프로그램 | 탭 처리, 네트워크 처리 |

## 내 프로젝트와 연결

`multichat-java`에서는 클라이언트가 접속할 때마다 `ClientSession`이 만들어지고, 이 작업이 `ExecutorService`의 스레드에서 실행됩니다.

```text
클라이언트 1 -> ClientSession 1 -> Thread
클라이언트 2 -> ClientSession 2 -> Thread
클라이언트 3 -> ClientSession 3 -> Thread
```

이렇게 하면 한 클라이언트가 메시지를 입력하지 않고 기다리는 동안에도 다른 클라이언트의 메시지를 처리할 수 있습니다.

## 주의할 점

스레드는 같은 메모리를 공유하기 때문에 동시에 같은 데이터를 수정하면 문제가 생길 수 있습니다.

`multichat-java`에서는 접속자 목록인 `sessions`를 여러 스레드가 접근합니다. 그래서 일반 `HashSet`이 아니라 `ConcurrentHashMap.newKeySet()`을 사용했습니다.

## 30초 면접 답변

프로세스는 실행 중인 프로그램이고, 스레드는 그 프로세스 안에서 실제 작업을 수행하는 실행 흐름입니다. 스레드는 같은 메모리를 공유하기 때문에 생성 비용이 비교적 작지만, 동시에 같은 데이터에 접근할 때 동시성 문제가 생길 수 있습니다. 제 채팅 서버에서는 여러 클라이언트를 동시에 처리하기 위해 클라이언트마다 `ClientSession`을 만들고 Thread Pool에서 실행했습니다.
