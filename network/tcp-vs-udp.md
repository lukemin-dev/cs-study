# TCP vs UDP

## 한 줄 정의

TCP는 연결 기반의 신뢰성 있는 전송 방식이고, UDP는 연결 없이 빠르게 데이터를 보내는 전송 방식입니다.

## 왜 필요한가

서비스마다 중요한 기준이 다르기 때문입니다.

```text
정확성이 중요함 -> TCP
속도와 실시간성이 더 중요함 -> UDP
```

채팅, 파일 전송, 웹 요청처럼 데이터가 빠지면 안 되는 경우에는 TCP가 적합합니다. 반대로 실시간 게임, 음성 통화, 영상 스트리밍처럼 일부 데이터 손실보다 지연 시간이 더 중요한 경우에는 UDP를 고려합니다.

## 핵심 차이

| 구분 | TCP | UDP |
| --- | --- | --- |
| 연결 | 연결 지향 | 비연결 |
| 신뢰성 | 높음 | 낮음 |
| 순서 보장 | 보장 | 보장하지 않음 |
| 속도 | 상대적으로 느림 | 상대적으로 빠름 |
| 예시 | 웹, 채팅, 파일 전송 | 게임, 스트리밍, DNS |

## 내 프로젝트와 연결

`multichat-java`는 Java Socket 기반 채팅 프로젝트입니다.

채팅 메시지는 중간에 빠지거나 순서가 바뀌면 사용자가 이해하기 어렵습니다. 그래서 UDP보다 TCP가 더 적합합니다.

다만 TCP는 메시지 단위가 아니라 바이트 스트림 단위로 동작합니다. 그래서 `multichat-java`에서는 메시지 앞에 4바이트 길이를 붙이는 length-prefix 방식으로 메시지 경계를 직접 구분했습니다.

```text
[메시지 길이 4바이트][실제 메시지 내용]
```

## 30초 면접 답변

TCP는 연결을 맺고 데이터의 순서와 재전송을 보장하는 전송 방식이고, UDP는 연결 없이 빠르게 보내지만 손실 가능성이 있는 방식입니다. 제가 만든 채팅 프로젝트에서는 메시지가 누락되거나 순서가 바뀌면 안 되기 때문에 TCP Socket을 사용했습니다. 대신 TCP는 스트림 기반이라 메시지 경계를 보장하지 않기 때문에, 메시지 길이를 먼저 보내는 length-prefix 방식으로 메시지를 구분했습니다.
